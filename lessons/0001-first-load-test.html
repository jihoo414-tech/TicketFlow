가짜 회원 5명이
동시에 찾아오면?

오늘의 목표: 이 프로젝트에 이미 있는 테스트가 무엇을 하는지 설명하고, 안전하게 실행할 준비를 합니다.

1. 부하 테스트는 무엇일까요?

매점에 손님이 한 명씩 오면 계산하기 쉽습니다. 손님이 한꺼번에 몰리면 줄이 생깁니다. 부하 테스트는 컴퓨터로 가짜 손님을 만들어, 우리 프로그램이 얼마나 빠르게 응답하는지 살펴보는 실험입니다.

여기서는 k6라는 도구가 가짜 손님 역할을 합니다. 이 손님을 가상 사용자(VU)라고 부릅니다. k6 공식 설명

2. 우리 프로젝트의 실험 읽기

perf/smoke.js에는 이미 첫 실험이 있습니다.

vus: 5
duration: '30s'
http.get('http://localhost:8080/api/members')
sleep(1)
가상 사용자 5명이 30초 동안 회원 목록을 반복해서 요청합니다. 각 가상 사용자는 요청 후 1초씩 쉽니다.

가상 사용자 5명은 실제 회원 5명이 아닙니다. 이 테스트는 회원 목록 조회를 시험합니다. 좌석 선점이나 결제는 아직 시험하지 않습니다. 따라서 이 결과로 예매 오픈 때 버틸 인원을 알 수 없습니다.

잠깐 퀴즈: 이 테스트로 같은 좌석을 두 명이 선점하는 상황을 확인할 수 있나요?

아니요. 이 스크립트는 회원 목록을 읽기만 합니다. 선점 요청을 보내는 별도 실험이 필요합니다.

3. 실행하기 전에

이 컴퓨터에는 k6가 설치되어 있습니다. 확인한 시점에는 앱이 실행 중이 아니었습니다. 테스트는 앱이 localhost:8080에서 실행 중일 때 그 앱에 요청을 보냅니다.

중요: 앱을 새로 켜기 전에 DB가 테스트 전용인지 확인하세요. 현재 앱 설정은 시작할 때 테이블을 삭제하고 다시 만드는 schema.sql을 실행합니다. 보관할 데이터가 있는 DB에 연결하면 안 됩니다. 이미 안전한 테스트용 앱이 실행 중인지 확실하지 않다면 먼저 저에게 물어보세요.

안전한 테스트용 앱이 이미 실행 중이라면, 프로젝트 폴더에서 PowerShell에 입력합니다.

k6 run perf/smoke.js

이 명령 자체는 기존 회원 목록 조회를 반복합니다. 앱을 시작하거나 테스트 DB를 만들지는 않습니다. k6 실행 문서

4. 결과에서 두 가지만 보기

http_req_failed는 k6가 실패로 분류한 요청의 비율입니다. 이 스크립트의 목표는 1% 미만입니다.

http_req_duration p(95)는 요청 100개 중 약 95개가 이 시간 안에 끝났다는 뜻입니다. 목표는 500ms 미만, 즉 0.5초 미만입니다. 결과 읽기

status is 200은 응답 상태를 확인한 결과입니다. check 실패와 전체 통과 기준인 threshold는 서로 다릅니다. 차이 보기

잠깐 퀴즈: p(95)가 300ms라면 모든 요청이 300ms보다 빨랐을까요?

아니요. 약 95%가 300ms 이하라는 뜻입니다. 나머지 요청 중에는 더 느린 것도 있을 수 있습니다.
