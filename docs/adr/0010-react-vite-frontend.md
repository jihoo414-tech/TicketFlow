# 프론트는 React + Vite + TypeScript, 빌드 결과물을 Spring이 서빙한다

정적 HTML 한 파일로는 화면이 늘어날수록 관리가 어려워 프론트를 React로 옮긴다. 화면이 거의 실시간 데이터(좌석 상태, 선점 남은 시간)라서 서버 렌더링으로 얻을 것이 없다. 그래서 Next.js 대신 Vite로 정적 파일을 빌드하고, Spring이 그 파일을 서빙한다. 실행하는 서버는 계속 하나다. 스타일은 Tailwind CSS로 쓴다.

## Considered Options

- **Next.js**: 파일 기반 라우팅과 서버 렌더링이 강점이다. 하지만 Node 서버가 하나 더 생기고, 정적 export로 쓰면 그 장점 대부분이 사라진다.
- **정적 HTML + 순수 JS 유지**: 도구가 필요 없다. 하지만 페이지를 나누고 상태(선택 좌석, 남은 시간)를 다루는 코드가 한 파일에 계속 쌓인다.
