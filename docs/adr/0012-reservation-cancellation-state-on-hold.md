# 예매 취소 상태는 선점(`hold.status`)에만 둔다

예매 취소는 선점의 상태를 `RESERVED`에서 `RESERVATION_CANCELLED`로 바꾸는 일이다. `reservation` 테이블에는 상태 열을 두지 않고, `hold_seat` 행도 지우지 않는다. 좌석이 차지되었는지는 지금처럼 `hold.status`와 만료 시각으로만 판단한다(`HoldSeat.isOccupying`). 그래서 선점 취소, 선점 만료, 예매 취소 모두 "좌석을 차지하지 않는 선점 상태"라는 같은 방식으로 좌석을 연다(불변식 2).

## Considered Options

- **`reservation.status`를 추가하고 둘 다 바꾸기**: 예매 쪽 조회에서 선점을 조인하지 않아도 된다. 하지만 같은 사실을 두 곳에 적게 되어 서로 어긋날 수 있다. 좌석 점유 판단은 어차피 `hold.status`를 보므로 진실의 원천이 둘이 된다.
- **예매 취소 시 `hold_seat` 행 삭제**: 좌석이 비었다는 게 행의 유무로 드러난다. 하지만 ADR 0011은 "좌석 id는 한번 만들어진 뒤 바뀌지 않는 `hold_seat`에서 락 없이 구한다"를 전제로 한다. 행을 지우면 뒤이은 같은 예매 취소 요청이 빈 좌석 목록을 받아 좌석 락 없이 진행한다. 어떤 좌석이 예매되었는지 이력도 사라진다.

## Consequences

- `reservation` 행은 만들어진 뒤 바뀌지 않는다. 그래서 예매 취소는 예매를 좌석 락 전에 읽어도 된다(ADR 0011).
- 예매 쪽 조회(내 예매 목록 등)에서 취소 여부를 보려면 선점을 함께 읽어야 한다.
- 취소 응답의 `status`는 선점의 상태(`RESERVATION_CANCELLED`)다.
- 확인 순서는 "이미 취소됨 → 회차 시작 전"이다. 이미 취소된 예매는 회차가 시작된 뒤에 다시 취소를 요청해도 아무것도 바꾸지 않고 성공으로 응답한다(멱등성 우선). 순서를 반대로 하면 같은 요청이 409가 된다.
- 회차 시작 시각 판단은 좌석 락 직후 읽은 시각(`lockedAt`)으로 한다. 회차 시작 시각 정각부터는 취소할 수 없다(불변식 11).
