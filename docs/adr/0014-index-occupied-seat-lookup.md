# 좌석 점유 이력 조회를 위한 복합 인덱스

좌석 조회는 `hold.showtime_id`가 일치하고 `status`가 `RESERVED`이거나, `HELD`이면서 `expires_at`이 현재보다 늦은 이력을 찾는다. 기존 회차 단일 인덱스의 실행계획은 회차에 속한 만료 이력까지 읽은 뒤 필터링했다.

실험용 스키마에 `hold(showtime_id, status, expires_at)` 인덱스를 추가한다. 12,000건의 만료 선점으로 구성한 로컬 실험에서 MySQL은 복합 인덱스의 조건별 범위 조회를 선택했다. 상세 조건과 k6 결과는 `perf/2026-10-30-복합-인덱스-측정.md`에 기록한다.

인덱스는 선점 생성과 상태 변경 시 유지 비용 및 저장 공간이 추가된다. 활성 선점·예약이 섞인 경우, 쓰기 성능과 운영 환경 효과는 검증되지 않았다. 기존 데이터베이스의 `spring.sql.init.mode=never` 환경은 스키마 파일 변경만으로 인덱스가 추가되지 않으므로 별도의 관리된 마이그레이션이 필요하다. `schema.sql`은 기존 테이블을 삭제하므로 기존 데이터베이스에 적용해서는 안 된다.
