# 시각은 DATETIME + LocalDateTime(한국 시간)으로 저장하고, 현재 시각은 주입된 Clock에서 읽는다

회차의 시작 시각과 예매 오픈 시각은 `DATETIME` 컬럼과 `LocalDateTime`으로 다룬다. 모든 값은 한국 시간(Asia/Seoul) 기준이다. 앱은 `now()`를 직접 부르지 않고, `Asia/Seoul`로 고정한 `Clock` 빈에서 현재 시각을 읽는다. 테스트는 이 빈을 시각을 직접 정하거나 앞으로 돌릴 수 있는 시계로 바꾼다.

## Considered Options

- **`TIMESTAMP` + `Instant`(UTC)**: 시점을 정확히 표현한다. 하지만 MySQL이 커넥션 타임존에 따라 값을 변환하므로, 로컬 MySQL과 Testcontainers MySQL의 설정이 다르면 같은 값이 다르게 읽힐 수 있다. 2038년까지만 저장할 수 있다는 한계도 있다. 채택하지 않았다.

## Consequences

- 값에 타임존 정보가 없으므로 "모든 시각은 한국 시간"이라는 약속을 지켜야 한다. 해외 공연을 다루게 되면 다시 판단한다.

## 테스트용 시계

- 테스트 소스의 `TestClock`이 `Clock`을 상속해 시각을 정하고(`setTo`) 돌릴(`advance`) 수 있게 한다. 공유 테스트 설정에 `@Primary` 빈으로 등록해서 컨텍스트가 한 번만 뜨게 한다. 여러 스레드가 읽어도 안전하도록 시각을 `AtomicReference`에 둔다.
- 기본 시각은 실제 현재 시각이 아니라 고정 상수(`TestClock.DEFAULT_NOW`)다. 실제 날짜가 바뀌어도 테스트 결과가 달라지지 않는다.
- 시계 빈은 롤백되지 않는다. 시각에 따라 결과가 달라지는 테스트 클래스는 `@BeforeEach`에서 `reset()`을 부른다.
- "테스트에서 시계를 고정/이동할 수 있다"는 첫 시간 규칙의 기능 테스트가 이 시계로 통과할 때 확인된 것으로 본다. 지금은 시각에 따라 결과가 달라지는 공개 API가 없기 때문이다.

### Considered Options

- **`threeten-extra`의 `MutableClock`**: 검증된 구현이지만 기능 하나 때문에 새 라이브러리를 들여야 한다. 채택하지 않았다.
- **`@MockitoBean Clock`**: ADR 0005의 "Mock을 쓰지 않는다"에 어긋난다.
- **테스트마다 `Clock.fixed`를 설정**: 설정이 다르면 컨텍스트가 여러 번 뜨고, 시각을 앞으로 돌릴 수 없다.
- **테스트 공통 메타 애너테이션에 초기화를 넣기**: 빠뜨릴 일은 없지만 숨은 동작이 생긴다. 테스트 클래스가 늘어나면 다시 판단한다.
