좌석 조회: 레코드에서 화면까지

현재 인덱스와 복합 인덱스를 비교하며 조인이 어디서 일어나는지 따라갑니다.

작은 예시입니다. 현재 시각은 10:00, 조회할 회차는 1번입니다. 아래 4건은 이해를 돕기 위해 만든 예시이며, 실제 12,000건 성능 실험 데이터는 모두 만료된 선점이었습니다.

실제 실행계획에서는 복합 인덱스로 두 범위를 탐색했습니다. 인덱스는 실제 DB 레코드 전체를 대체하는 것이 아니라, 필요한 레코드를 더 빨리 찾도록 돕습니다.

서버 애플리케이션이 좌석 ID를 기준으로 두 결과를 합칩니다. 점유 정보가 없는 좌석은 AVAILABLE입니다.

A-3RESERVED · 예약 완료

여기서 전체 seat 목록을 합치는 과정은 DB JOIN이 아니라 애플리케이션의 Map 조회입니다. 회차 정보도 별도로 조회합니다.

실제 12,000건 실험에서는? 모든 이력이 만료되어 점유 이력이 0건이었고, 따라서 hold_seat 조인은 실행되지 않았습니다. 그 실험에서 기존 인덱스는 12,000건을 읽고 걸렀고, 임시 테이블의 복합 인덱스는 조건에 맞는 범위를 탐색해 0건을 찾았습니다.

초록색 행은 예시에서 현재 점유 중인 이력입니다. 이 화면은 개념 설명용이며 레코드와 인덱스의 물리적 배치를 그대로 재현하지 않습니다.
