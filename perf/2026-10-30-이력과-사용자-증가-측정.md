# 좌석 선점 이력과 사용자 증가 실험

## 목적과 시나리오

6,000석 공연에 12만 명이 관심을 보이는 20:1 경쟁 상황을 가정한다. 경쟁률만으로 좌석 조회 API의 동시 사용자 수는 결정할 수 없다. 모든 사용자가 한꺼번에 좌석 화면에 진입하는지, 시간에 걸쳐 진입하는지, 대기열을 거치는지에 따라 부하가 달라진다. 이번 실험은 12만 명을 재현한 실험이 아니라, 좌석 선점 이력과 좌석 조회 VU가 각각 늘어날 때의 변화를 살펴보는 로컬 실험이다.

## 측정 조건

- 일시: 2026-10-30, 로컬 Windows PC.
- `codex/seat-performance` 브랜치의 Spring Boot 서버(포트 18080), Docker MySQL 8.4.11, k6 2.2.0. 서버·DB·k6가 같은 PC의 자원을 공유한다.
- 테스트 전용 DB `ticketflow_perf_matrix_20261030`, 회차 ID 1, 6,000석. 실험 종료 시 이력 12,000건 모두 만료된 `HELD`임을 확인했다.
- SQL 로그 비활성화. 각 조건별 5초 예열 후 30초 측정, 1회씩 실행했다. 1,000건 측정 후 서버를 재시작하고 6,000건부터 측정했다.
- 각 VU는 좌석 조회 응답을 받은 뒤 1초 대기하고 다시 요청한다. `checks`는 HTTP 200만 확인한다. p95는 HTTP 요청의 95퍼센타일이다.

## 실험 1: VU 5명 고정, 선점 이력 증가

| 만료 이력 | VU | 완료 요청 | 초당 요청 | 평균 | p95 | 최대 | 실패율 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1,000건 | 5 | 140 | 4.55 | 88.56ms | 146.52ms | 157.12ms | 0% |
| 6,000건 | 5 | 121 | 4.00 | 247.84ms | 316.60ms | 436.96ms | 0% |
| 12,000건 | 5 | 106 | 3.48 | 431.16ms | 538.29ms | 621.14ms | 0% |

같은 VU 설정에서 이력이 늘수록 응답 시간이 증가했다. 12,000건의 p95는 1,000건의 약 3.7배였다. 단계마다 서버 상태와 실행 시점이 달라 이력만이 유일한 원인이라고 확정할 수는 없다.

## 실험 2: 이력 12,000건 고정, VU 증가

| 만료 이력 | VU | 완료 요청 | 초당 요청 | 평균 | p95 | 최대 | 실패율 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 12,000건 | 5 | 106 | 3.48 | 431.16ms | 538.29ms | 621.14ms | 0% |
| 12,000건 | 20 | 263 | 8.07 | 1.40초 | 1.90초 | 2.34초 | 0% |
| 12,000건 | 50 | 314 | 9.06 | 4.17초 | 4.93초 | 7.61초 | 0% |

50 VU에서 20 VU보다 p95가 약 2.6배로 늘어난 반면 초당 완료 요청은 약 8.07건에서 9.06건으로 소폭 늘었다. 심한 지연과 처리량 증가 둔화가 보여, 로컬 장비에 추가 부담을 주지 않도록 계획했던 100 VU는 실행하지 않았다. HTTP 오류는 없었지만 모든 검사가 정상 응답 상태만 확인하므로 응답 내용의 정확성까지 보장하지는 않는다.

## 해석과 한계

두 실험 모두 각 단계에서 한 번만 측정했다. DB 실행 계획, JVM 프로파일, CPU·메모리, 커넥션 풀을 수집하지 않았으므로 특정 병목이나 최대 처리량을 확정할 수 없다. 컴퓨터에서 서버와 부하 생성기가 자원을 공유한 영향도 포함된다. 또 응답이 느려지면 각 VU의 다음 요청이 늦어지는 폐쇄형 테스트이며, 초당 요청 수는 서버의 최대 처리량이 아니다.

50 VU는 좌석 조회 스크립트의 가상 사용자 50명을 뜻하고, 실제 경쟁자 50명이나 실제 동시 요청 50개와 항상 같지 않다. 데이터는 전부 만료된 선점이라는 단순한 분포다. 12만 명의 유입을 재현하려면 입장 시간, 대기열, 좌석 화면 진입 비율과 갱신 주기, 선점·결제 행동을 별도로 정해야 한다.

원본 k6 요약은 `result-matrix-1000-vu5.json`, `result-matrix-6000-vu5.json`, `result-matrix-12000-vu5.json`, `result-matrix-12000-vu20.json`, `result-matrix-12000-vu50.json`이다. 테스트 서버는 실험 후 종료했고 테스트 DB는 보존했다.
